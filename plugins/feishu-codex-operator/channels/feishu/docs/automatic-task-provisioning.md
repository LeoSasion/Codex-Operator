# Channels 首次选择、项目与默认任务

日期：2026-09-21。状态：本机两项授权均已明确批准，原生项目和首批任务已创建。
后台自动登记已实现于 `operator_core/user_tasks.py`，部署与真实新用户创建的验收分别记录；
首批由助手通过原生工具创建、已有任务的收发成功均不能冒充新用户自动创建已通过实机验收。

## 首次选择与授权

首次接入 Channels 先读取已有选择和授权。没有中继选择时，让用户明确二选一：

| 选择 | 向用户说明的区别 |
|---|---|
| Luna/low | 使用 Codex 账号的 Luna 做固定转交，使用模型额度；仍须核对任务实际模型。 |
| 本地 Beeper 伪模型 | 用本机固定程序完成转交，不需要模型推理；当前原生接入仍待验证，文件安装成功不等于已可使用。 |

不提供 Spark。两者都用于同一个名为 `Beeper` 的固定转交任务，不决定用户业务任务的模型。
现有明确选择继续沿用，本机所有者当前选 Luna/low；这不是替其他首次用户做出的选择。
底层空配置兼容默认 Luna 也不能当作首次用户已同意。选择与来源记录到私有配置回执，
随后按选定模式配置；本地方案无法通过原生核验时保留选择并报告准确缺口，不能暗中改用 Luna。

当通道没有可用的默认项目或原任务已经确认缺失时，同时收集以下两项独立授权。
可与上面的二选一放在同一次引导中，已回答的项不重复询问：

1. 创建并配置 `{Channel name} Operator` 本地项目，例如 `Feishu Operator`。
   先核实当前 Desktop 的默认新项目位置；本机 26.915.4065.0 为文档目录下的
   `ChatGPT/{项目名}`，而不是假定直接放文档根目录。此项包括名为 `Beeper` 的
   固定转交任务，以及一个以当前已核验飞书用户姓名显示的默认业务任务。
2. 在该项目中，为已获准使用机器人的用户按需自动创建并续用任务；任务显示
   飞书用户姓名。授权长期有效，直至所有者撤销，不对每个新用户重复询问。

项目授权与持续建任务授权分开记录；允许创建项目不等于允许日后自动建任务。
既有授权、登录及配置继续沿用。目录、任务和绑定的实际创建与读回验证完成后，
才报告配置成功。相同名称的未知目录或 Desktop 项目不能被直接接管。

## 由助手完成的创建流程

1. 核对现有登录、准确应用/用户身份、原生项目和已保存绑定，复用所有仍有效的内容。
2. 获准后由助手创建项目目录，并通过当前可用的原生项目入口登记，读回准确项目 ID、
   路径及 local 属性。不能用当前研发目录代替通道项目，或把 projectless 任务称作该项目。
   若原生界面要求 `Trust folder`，由用户完成这一次信任决定，其余创建由助手继续。
3. 用原生 `create_thread` 创建固定 `Beeper` 和首个用户任务，保存准确返回的 UUID。
   本地非 Git 项目选 local 环境；用户任务使用自身原生默认模型，不套用转交模型。
   已有准确记录则核对并复用；创建结果不确定时保留记录，不再创建第二份。
4. 按用户所选方案配置 Beeper。Luna/low 用原生任务工具明确设置，并核对新回合的实际模型；
   本地伪模型按其 provider 接入流程核验，不能只改模型字符串、接管全局原生路由或宣称
   目录项可见即成功。业务输入和旧失败不作模型校准请求。
5. 由助手登记固定 Beeper、Final Callback 与当前用户的准确飞书绑定；获准持续自动建任务
   时，在停机且无待处理消息的条件下执行 `channels user-tasks-configure`，记录已建首个任务。
   未获持续授权则保留已获准创建的项目/首个任务，后续使用 `/init` 手动选择，不启用自动登记。
6. 分别报告项目/任务创建、所选转交方式接入和实际收发验证的结果。已授权自动绑定的用户
   可直接发普通消息；`/init` 保留为主动选择/改绑入口，不成为必做的额外一步。

## 任务选择顺序

1. 飞书端已明确保存、仍有效的准确任务绑定优先，即使它位于其他项目。
2. 没有有效显式绑定时，复用此通道身份下已经登记给同一用户的可用任务。
3. 确认没有可续用任务，且持续授权有效时，才在默认项目创建一个新任务，
   保存返回的任务 UUID，再承接原消息。

“新用户”指没有可续用任务的用户，不限于刚加入企业的成员。名称仅用来显示；
识别使用通道、企业/应用范围和用户 ID，投递使用准确任务 UUID。改名不新建，
同名不合并；只有同名标题而没有身份关联的现有任务不能被自动认领。
私聊的辅助消息查询仅补充同一已准入 sender ID 的显示姓名；若查询返回不同
sender ID，保留原事件身份且不采用该姓名，避免给另一用户登记任务。

首批自动用户任务面向私聊。群聊和话题继续按原会话范围隔离，已有绑定优先；
不把群消息接到某个成员的私人任务。此授权不扩大机器人当前的访问名单。

## 缺失、失败与并发

任务列表的一页、超时、断网、权限错误或暂时读不到不能证明任务不存在。
旧绑定确认缺失时保留原 UUID 和原因，先由所有者审核；当前不会自动替换缺失绑定。
明确归档的任务保留归档意图，不自动恢复；不因重启、目录刷新而重复建任务。

同一用户同时到达的首批消息只共享一次创建操作。创建前保存唯一操作记录；
收到准确结果后登记。结果不确定时等待核对，不再发第二次创建请求。成功建任务
不表示原消息已投递；业务投递仍使用现有去重和一次转交机制，原失败不重放。

撤销持续授权后停止新的自动创建，已有绑定和历史保留。用户重新手动绑定时，
新绑定立即高于自动任务登记；创建操作不能覆盖并发发生的手动选择。

## 实施边界

- 管理配置持久保存准确项目身份、通道身份和分开的授权状态；不能从机器人消息、
  任务标题或旧失败记录推导所有者授权。
- 新的创建管理流程与只读 `/init` 目录分开；保留 Desktop 对任务的所有权。
  `/init`、额度读取和生命周期观察使用的 App Server 不增加创建、恢复或业务执行。
- 当前可用 Desktop 工具列出项目并在已登记项目创建任务，但未提供直接注册本地
  项目的工具。需要核实支持的项目注册入口；不能修改 Desktop 内部数据库，或
  用项目外的独立任务冒充已建立项目。若此步骤必须用户操作，只集中提示这一步。
- 获准用户的无绑定私聊进入独立登记队列。固定 Beeper 执行由私有授权生成的
  固定管理程序：核对准确原生项目、创建一次任务、查看一次进度，随后在项目内
  `.operator/task-receipts` 独占写入准确返回身份。管理操作不含飞书业务正文，
  不使用 Final Callback；Beeper 不决定用户身份、项目、绑定或业务结果。
- Operator 用只读原生接口核对新任务仍活跃、属于准确项目，并复查授权和当前绑定。
  成功登记后，原消息才进入既有业务转交。既有用户按应用范围和用户 ID 复用；
  元数据回执是本地登记信息，不是身份认证、执行证明或业务答案。
- 同时只运行一个登记 worker，最多 32 项待登记、500 个用户记录；单次创建等待
  180 秒。达到边界、超时、队列拒绝或创建结果不确定均停止，保留记录，不重试、
  不换模型再试、不自动创建替代任务。管理操作不刷新原有 wake lease。
- 首版项目须已登记为本地非 Git 项目；变化后停止自动创建并请所有者审核。
  所有任务仍由原生工具创建，继承原生默认模型和权限。
- 新旧状态迁移须保留既有显式绑定和缺失任务记录。先验证授权分离、同名/改名、
  首消息并发、手动绑定优先、已确认缺失与读取不确定，再做用户消息→原生任务→
  Final Callback→同一飞书私聊的完整验收。

## 管理入口

由助手准备私有授权文件，保留两项独立授权、准确项目/应用/机器人和固定转交任务身份。
停机、没有待处理消息时执行 `channels user-tasks-configure -GrantFile <授权文件>`。
它可登记经原生核对的首个已有用户任务，避免重复新建；不同或不完整的旧记录不覆盖。
登记已有任务要求私有记录与当前飞书准确绑定完全一致，并读取原生无正文元数据核对身份
和实际项目目录；此操作不改变绑定，不因原生列表漏项否定已经核实的现有绑定。
日后的自动重绑/复用仍须确认准确任务未归档，列表漏项不能作为再次创建的理由。
活跃目录查询显式包含所有模型提供方，避免任务切换提供方后被默认筛选漏掉；仍保留
原有来源、归档、准确身份和分页边界。

原生普通列表可能滤掉空摘要的 paginated 任务。完整有界列表未命中时，登记流程可对
已经持有准确 UUID 的任务读取无正文元数据，再用同一个 App Server 返回的 Codex home
进行一次 v5 索引只读检查。要求默认 SQLite 位置、已知表结构、未归档、空摘要、相同
身份/来源/提供方/创建更新时间/真实项目目录及 rollout 文件身份；Windows 本地驱动器
的扩展路径拼写按相同文件核验。自定义存储、更新的数据库版本、分页不完整、历史模式
或身份不符均停止并保留登记。没有扫描或修改历史，也不修复原生索引。
这只补自动登记的准确任务核验；`/init` 仍用原生目录，不能据此宣称其空摘要任务已可见。
依据：[官方状态索引的空摘要过滤](https://github.com/openai/codex/blob/main/codex-rs/state/src/runtime/threads.rs)。
`channels user-tasks-status` 只读查看是否启用；`channels user-tasks-revoke` 停止新登记，
保留已有任务、绑定和历史。授权文件、用户登记库及回执均不进入开源包。
