# 2026-10-02 拓展模式升级说明

本包是本地 preview。保持官方原生入口及已有聊天，模型/工具的实际验收范围以
[发布审计](release-audit.md)为准。解压后以 `plugins/feishu-codex-operator` 为唯一源码，
不覆盖安装 runtime/cache 或复制本机私有配置、凭据、历史和验收回执。

1. 保留旧源码与私有安装、入口、恢复记录。读取[安装与恢复指南](../../shared/docs/installation-and-removal.md)。
   从“文件 → 退出 ChatGPT”正常退出准确拓展实例，并确认进程退出回执；关闭窗口可能只隐藏
   驻留实例，不能据此停止路由。官方原生窗口可保持运行。沿既有受管服务入口正常停止拓展路由，
   检查空闲确认、精确进程退出与独占端口可用。失败/不确定记录须独立复核，不能重跑旧事务。
2. 若同时升级 Web 源码，先正常停止保存的 Web 服务，再用既有 settings/Python 执行
   `models web configure`。显式 `models web start` 准备空页；状态 ready/idle 后再次显式
   `start` 仅核对复用并完成绑定，应返回 `reused=true`。准备和状态不发送模型请求。
   保留登录与固定连接。要求登录前必须观察并复查当前准确页面，先排除瞬时加载/验证
   提示；不能凭历史失败或一次短暂提示要求用户操作。
3. 已安装模式入口须使用配对刷新，不使用独立 refresh。先将私有注册候选放在项目 `.codex`
   下，只更新已有 Responses 合同/下调容量，不换端点、凭据、型号或顺序。运行：

   ```powershell
   $operatorMaintenancePython = '<保存 Web 服务所绑定的 Python 绝对路径>'
   $operatorMaintenanceScript = '<此包中 scripts/operator_mode_maintenance.py 的绝对路径>'
   & $operatorMaintenancePython -X utf8 -E -s -B $operatorMaintenanceScript pair-prepare --root <准确隔离目录> --registry-file <私有候选绝对路径> --web-profile <保存Web服务目录绝对路径>
   & $operatorMaintenancePython -X utf8 -E -s -B $operatorMaintenanceScript pair-preview --root <同一目录> --stage <prepare返回的stage>
   & $operatorMaintenancePython -X utf8 -E -s -B $operatorMaintenanceScript pair-apply --root <同一目录> --stage <同一stage> --expected-preview-sha256 <preview返回的摘要>
   ```

   使用登记的准确解释器；通用 PowerShell 包装入口从 PATH 选择 Python，不能保证与保存的
   Web profile 相同。解释器不符会在准备分配事务前拒绝，不能静默换解释器或重跑不确定事务。
   只刷新源码、不更换后端时省略两个后端选项。Web 取消观察的设置必须已明确绑定该隔离
   home。配对事务保留完整 home、原生快捷方式和所有旧归属材料，不启用全局路由。
   若官方应用已升级，在保持同一官方包家族、版本严格前进的情况下，给本次 `pair-prepare`
   增加 `--package-update`。普通启动不会自动接受包变化。此选项保留原包身份、摘要与入口
   原件，重新检查当前 Appx manifest/程序，沿同一 preview/apply 事务更新绑定；不重建 home、
   复制登录或重设已用引导偏好。包、原生配置或候选变化后原预览不再有效。
4. 从受管拓展快捷方式打开选择窗，选拓展，在原生模型菜单选择准确型号。只提交不同的
   新验收输入；旧失败不重试。分别核对文字、续聊、实际工具参数/结果、文件、审批和停止。
   同菜单可见、HTTP 完成和助手声称成功都不能代替这些检查。
5. Huihui 使用[准确模板兼容](../../models/local/docs/huihui-template.md)。这是该机器保存原设置
   后的显式操作，不是升级脚本的默认副作用；未知模板或后续编辑必须保留。

受管 Web 请求读取期限现在与既有 900 秒 MCP 上限一致，API/Local/原生保持 300 秒。
浏览器的配置期限、容量、单次读取、权限和零重试没有扩大。未验证的型号继续保留未验证
状态；GPT-6 Pro 的当前账号额度不从目录或旧结果推定。

若保留的是保存身份前的准确早期空引用启动失败，先沿[窗口维护说明](../../models/common/docs/mode-entry-window.md)
正常退出该拓展实例和失败提示、选择器，再以同一 Python/脚本执行 `startup-preview --root … --attempt …`
及摘要绑定的 `startup-review`。复核保留原失败、当前选模和全部原件，不制造正常退出，
也不自动重开；随后 `service-stop` 确认原路由停止，新的升级使用新事务。其他故障保持阻塞。

若官方更新/重启后准确路由进程已消失，仅完整且未开始 stop/其他维护的 `intent/running`
记录可做独立缺席复核：正常退出拓展和选择器，运行
`router-absence-preview --root …`，再以其摘要运行
`router-absence-review --root … --expected-preview-sha256 …`。
复核要求原件未变、该目录在所有官方包代次下都无进程、路由端口可独占；仅保存异常代次
的原件和复核，不制造正常停机或请求空闲证明。无法观察、仍运行或部分记录保持拒绝。
之后以新 `pair-prepare --package-update` 和新显式入口启动恢复；旧失败/取消输入永不回放。

本机 10 月 2 日恢复已在官方 26.930.2377.0 完成，原聊天列表和当前原生窗口保留。
CLI 0.159.0-alpha.12.1 的九项隔离工具/搜索/压缩检查通过；实际 Web、Local、审批和
复杂工具以最新发布审计中的各项结果为准，不能从入口恢复推定全部可用。
当时的检查范围：更新后的 Huihui 手动压缩与新文件接续已通过。Web 搜索实际完成两次工具
往返，但最终回答超时；原生 Stop 准确取消新回合，浏览器保留未通过。恢复空白页后的
ready/idle 不改判这些失败。该次源码的完整回归为 1,632 Python（30 跳过）及 134 Node 全部通过；
审批、自由格式 patch 和主窗口全容量自动压缩仍未确认。升级不会重放这些验收输入。

后续 Web 实机确认用户与助手属于不同的角色回合；助手的 ID 序列并不包含原用户或
原用户回合前缀。当前渲染列表也只保留已挂载的一侧。旧身份序列候选及它们的失败
记录仍保留，不能将测试通过解释为实机通过。新的受管空页绑定候选使用原文、用户
身份、独立页面与单次请求记录。首次候选的绑定失败和后续快速回复的时序失败保持
原结果。现把原文核对、当前 app 分隔投影、原用户身份和文档捕获合并为一次同步读取，
思考阶段身份读取与最终内容读取仍分开。不同的新普通回复、同聊接续、实际文件读取
及实际原生搜索已经分别通过；另一条新原生 Stop 完成一次网页停止和稳定空闲后，
准确浏览器被保留，不同新输入沿用它并正确接续。该检查点的冻结 Web 回归通过 417 Python
及 152 Node，入口维护的独立冻结回归通过 54 项；旧失败没有改判或重放。
搜索答复及官方链接已在只读重选聊天后的原生无障碍视图确认；该窗口截图采集黑屏，
不据此声称即时绘制通过。审批、自由格式 patch、主窗口全容量自动压缩与其他型号
仍须独立验收。详细时间及界限见发布审计。

后续当前窗口画面已恢复，完整搜索答复、官方链接和原生搜索过程均可见。
一条不同的新普通输入在 28.853 秒完成，答复自动出现在同聊窗口，无需重选或重载；
准确浏览器仍是同一次启动。无障碍快照曾落后于画面，收起模型菜单后也显示准确
答复和空闲输入。旧黑屏/锁屏采集原因未确认，此复核没有改变隐私设置或重放输入。
这是该次可见画面的验收，不是首字/绘制时间测量，也不扩大审批、patch、自动压缩、
其他型号或普遍 UI 稳定性的验收范围；原生配置、历史字节前缀和旧回执均保留。

新副窗口恢复后，Web 实际读改测、停止后的浏览器保留和不同新输入续聊均完成。
Huihui 在原 32768 配置下通过普通输入触发的自动压缩，以及压缩后的新文件接续；
其中一次工具参数拒绝按原结果保留，后续执行单独核对。审批/拒绝、原生 freeform
patch 和其他未测型号仍未确认，不能将上述案例扩展为全部能力通过。

若配对应用失败后保留了 `pending.json`，即使当前文件似乎已回到旧版本，也不能重跑
该 stage 或直接删除事务。只有全部当前字节、入口归属链、迁移原件、生成目录和
全部受管原件位置均与完整回滚材料相符，且准确拓展进程不存在、路由已正常停止，
才可作显式只读预览与摘要绑定复核：

```powershell
& $operatorMaintenancePython -X utf8 -E -s -B $operatorMaintenanceScript rollback-pair-preview --root <准确隔离目录> --stage <原失败stage>
& $operatorMaintenancePython -X utf8 -E -s -B $operatorMaintenanceScript rollback-pair-review --root <同一目录> --stage <同一stage> --expected-preview-sha256 <本次preview摘要>
& $operatorMaintenancePython -X utf8 -E -s -B $operatorMaintenanceScript rollback-pair-status --root <同一目录> --stage <同一stage>
```

备份数量随受管范围而变，必须完整且逐字节匹配。复核只增加交叉绑定的保留回执，
不更改失败、pending、原件或安装字节，不声称原事务未写入或成功完成。之后才可
准备不同的新事务；原事务始终不可重试。缺失备份、后续编辑、仍运行或归属不明
保持拒绝。应用时摘要相同的受管文件保留原实体，并仍纳入完整备份及事务检查。
本轮入口维护的冻结回归通过 54 项；实际 Web 能力仍以独立实机结果为准。

恢复/卸载先解除准确受管服务与回调绑定，再恢复入口、Hook 和规则，最后归档拥有的 runtime。
原始任务、权重、凭据及其他设置保留；删除 Desktop 插件不会自动执行此恢复。
