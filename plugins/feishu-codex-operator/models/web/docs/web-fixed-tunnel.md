# 固定网页工具连接

首次配置以当前页面和[官方固定连接说明](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels)为准；下文标明日期的排查记录只描述当时的观察。

## 用户配置引导（助手执行）

目标是带用户完成一次固定连接。先用一句话解释：Tunnel ID 是这条连接的编号，运行
密钥是本机程序连接 OpenAI 所需的凭据。技术命令留给助手执行，步骤直接发在对话里，
不要求用户去侧边栏文件里找操作说明。

1. **打开连接页面。** 用可用浏览器工具打开
   [OpenAI Tunnels](https://platform.openai.com/settings/organization/tunnels)，显示给用户，
   并保留供其继续操作。先复用已有相关页，不重复弹窗；读取实际页面后再给操作提示。
   如果停在登录页，本轮只引导用户用对应 ChatGPT 账号登录并反馈结果，不同时堆叠后续步骤。
2. **取得连接编号。** 登录后核对目标组织与页面。已有准确固定连接则复用；首次配置
   才引导用户创建，名称可建议为“Operator 固定连接”。说明需要关联目标 ChatGPT
   工作区，个人账号使用其个人组织。以当前页面文字指明入口，不凭记忆编造按钮。
   页面提示无权限时先处理对应组织的 Tunnels 权限：创建需要 Read + Manage，
   运行需要 Read + Use；不要让用户反复创建临时插件。
3. **取得运行密钥。** 助手打开同一组织的
   [API keys](https://platform.openai.com/settings/organization/api-keys) 页面，说明本步用于
   给本机连接程序提供凭据。已有适用密钥则复用，否则用户自己创建普通运行密钥；
   不要求把 Admin Key 用于常驻服务。先确认本机输入窗口可用，再引导用户处理只展示一次
   的密钥；用户处理密钥期间，不读取、截图或输出含密钥的页面、输入框或剪贴板。
   只询问是否已保存。
   当前创建表单可先准备名称和所属项目，选择 `Restricted`，仅勾选 `Tunnels` 下的
   `Read` 与 `Use`（共两项）；不要把该项的 `All selected` 误读成全局 `All`。
   有效期遵循用户已有选择；要求不设到期时间且页面提供“永不过期”时选中该项。
   助手只准备可核对的表单，用户点击 `Create secret key` 并直接将密钥粘到本机窗口。
4. **保存到本机。** 助手准备并打开下面的本机配置表单，在对话中指明：把连接编号填入
   `Tunnel ID`，把运行密钥填入 `Runtime API key`，点击“保存到本机”；成功会显示
   “已保存”。用户无需编辑 JSON 或查找私有目录。当前工具不能打开表单时，说明限制，
   给出已经准备好的可点击本机入口及同样的对话步骤，不声称窗口已打开。
   已保存配置不重新填、不覆盖；助手只读取 `setup-result.json` 等无密钥结果继续检查。
   已从当前页面核实连接编号时，用 `--tunnel-id` 预填，用户只需输入密钥。
5. **检查并连接插件。** 按本次授权启动连接并检查实际状态。连接可用后，打开
   ChatGPT 插件页面，优先复用用户选定的浏览器与已登录页面。引导用户从“插件 → 新插件”选择 Tunnel 并填写同一
   编号；具体入口以当前界面为准。已有精确固定插件绑定则跳过创建。逐项告诉用户当前
   应填什么、预期结果和完成后的返回动作。插件授权完成后再检查绑定与实际请求，
   不把本地“已保存”或 `transport_ready` 说成整个流程成功。
   插件所属账号和工作区须与后台会话一致；只有后台会话需要人工登录或验证时，
   才显式打开 Operator 辅助窗口，不因配置插件额外弹出另一个窗口。
   临时聊天首次显示的插件访问状态可能尚未加载完成。等待公开状态变成可使用插件后
   再选择已绑定项；始终不可用时报告实际状态，不代替用户更改个性化。旧菜单公开
   应用编号时，选择前核对名称和编号。当前菜单可能只给出名称：仅当准确名称唯一时
   临时选中，随后必须从编辑器中已插入的应用标签核对准确应用编号，核对成功前不得
   输入正文或发送；同名、缺失或不匹配均停止。工具声明刷新与已安装应用的冻结快照
   是另一项检查，不能由本机 `tools/list` 一致或一次成功调用推断完成。

   首次工具验证还要区分读取与写入。插件默认“允许低风险操作”可能在网页层拦截
   写入；模型回复“Codex 拒绝”本身不能证明请求到达本机。先核对本机是否实际收到
   对应工具调用，再给用户解释。需要调整权限时，助手打开这个准确插件的“权限”页，
   说明作用范围、是否临时以及恢复方式，并取得所需确认；不降低工具风险标记来避开
   网页确认。真实文件写入和运行测试成功之前，不宣称编码已跑通。

   回复出现 `Connection failed` 时也要先核对实际调用：本机没有收到写入，不能说是
   本机拒绝或已经写入。连接在线也不能排除网页层失败。保留当前请求的终态、已执行
   调用及未执行步骤，直接在对话中说明；不通过重发同一请求或重建插件来猜测原因。

   状态命令的 `summary` 现在直接给出中文进度，`transport` 区分当前请求与最近一次
   结束请求。助手对用户说明“已转交几次调用、收到几份结果”，再核对实际产物及结果。
   配对结果也可能是拒绝或失败；这些计数不证明执行成功，更不证明用户任务全部完成。
   旧版本缺少此记录时，只能说证据缺失，不能填零或根据网页文字补造调用。

   已核实插件及权限、问题仍持续时，按[官方故障排查](https://help.openai.com/en/articles/20001497-troubleshooting-apps-in-chatgpt)
   保留失败时间及时区、准确插件编号、所选模型和本机收到的调用范围，准备去除密钥及
   私人内容的支持材料。应用权限不会覆盖平台安全保护；不要继续重建连接或调整风险
   声明来尝试通过。对外发送材料需要用户明确要求；本地准备诊断无需额外确认。

   生成中的页面状态现在单独识别：持续的单次工具确认、登录过期、订阅加载失败和
   回复错误会返回对应中文原因，自动等待结束且不自动弹窗。只有当前请求实际观察到
   的公开控件或提示才构成依据，模型自己写“安全检查拦截”不算。说明本次可能已有
   部分操作完成，系统不会自动重做；需要人工处理时，按错误引导到适用页面，不重复
   创建连接。单次确认被停止后不能声称辅助窗口仍保留原确认卡，也不能自动重发原操作。

   用户答复“已允许”时，先检查这个插件实际显示的权限；已生效就继续，不再让用户
   重做。按用户明确选择区分长期和临时授权：长期授权保存后继续沿用，不在测试结束时
   自动恢复，也不反复询问同一已完成的设置；临时授权的案例结束后恢复原设置，并核对
   保存结果。无论哪种方式，都只针对这个准确插件，不能扩大到其他应用或 Codex 权限。
   工具返回“文件不存在”
   这类执行结果要原样保留；不能靠修补代码、重放调用或抹除失败记录来通过验收。
   产物检查应单独核对文件字节与实际测试结果。

每步完成后保留进度，下次从尚未完成的步骤继续。窗口关闭、服务重启、用户等待都不
自动更换固定连接；默认不设本地到期时间。旧临时插件的成功添加记录仍有效，临时
地址失效与固定连接迁移应分别解释，不能归因于用户没有完成添加。

页面入口和权限以当前实际页面及
[官方固定连接说明](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels) 核对。
固定连接没有本地到期计时器，但账号权限、凭据和网络仍可能影响可用性。

### 登录报错时保留配置进度

登录回调报错不能证明会话没有建立。先在同一个标签页重新打开一次上面的 Tunnels
设置入口并核对结果；已进入设置就直接继续，不要求用户再登录。仍需登录时，让用户
使用原来的登录方式，参照 [官方登录排查](https://help.openai.com/en/articles/6613629-why-cant-i-log-in-to-the-openai-api-platform)。
保留用户选择的浏览器，不循环尝试登录，也不重放、复制或记录带认证参数的回调地址。
用户选择换浏览器时只打开干净的设置地址；登录问题不触发新建连接或重新添加插件。

### 显示“暂时没有可用的应用操作”

先保留已有插件，核对本机服务、固定隧道与后台浏览器各自的状态。固定隧道在线、
浏览器工作进程结束和网页详情未加载完成是不同情况，不能仅凭这句话判断连接失效。
本机服务恢复后，在同一个页面重新加载，进入已有插件的“管理”，等待详情加载完成；
有“刷新”按钮时刷新操作清单。助手应同时核对页面显示 `operator_begin`、
`operator_call`，以及本机是否实际收到并响应 `tools/list`，然后直接在对话里报告结果。
不要求用户重新创建隧道、运行密钥或插件，也不为恢复清单改变插件权限。

工具说明更新同样刷新这个已有插件。通用调用会如实标记可能访问外部环境；这是
说明修正，不是授予新工具或更改原生权限。刷新后核对用户原先选择的长期授权仍然
生效；若界面要求额外授权，报告实际变化，不能据“允许所有操作”假定新授权已完成。

新版辅助窗口可直接从已加载的只读插件详情/管理页关闭：它单次返回空白临时聊天，
核实就绪后隐藏并继续持有同一后台浏览器。无需让用户手动返回聊天。仅接受固定公开
路径和无草稿、编辑、权限弹层、登录及进行中刷新状态；不自动更改权限或重发请求。
2026-09-18 已在准确固定插件设置页完成实机关闭验收，同一进程恢复 ready，零模型
请求。旧版直接关闭导致浏览器终止的失败单独保留。

2026-09-16 的实际排查中，旧固定隧道仍在线，但后台浏览器已经结束，网页先显示空
操作清单、插件详情随后长时间停留在加载占位。助手显式停止空闲旧服务，复用同一个
私有配置启动新服务；重新加载和进入“管理”后两项操作恢复，刷新还产生了成功的本机
工具清单响应。操作清单恢复没有证明写入或完整编码成功，也不能单独证明空清单由
浏览器结束导致。

## 助手准备与开发配置

已有网页服务设置后，由助手按[当前原生 Web 体验规则](native-web-experience.md)
保存一次配置引用。此后从同一入口查看、启动、协助和停止，实例目录由程序创建，
不用让用户再次填写 Tunnel ID、运行密钥或新建插件。该入口不会自动修改 Codex 路由；
连接在线、浏览器可用及原生任务验收仍分别核对。

显式 `mcp.mode = openai_tunnel_v1` 使用同一个 OpenAI Tunnel ID。Python 服务重启后
更新本地 MCP 端口，保留固定隧道身份和准确的插件 ID/名称。服务默认没有到期计时器；
账号权限撤销、网络或客户端故障仍会使连接不可用，不能保证永久在线。

首次需要用户在同一账号所属组织创建隧道，并提供有 Tunnels Read + Use 权限的普通
runtime API key。创建/管理隧道的权限与运行权限不同；管理密钥不用于常驻服务。
ChatGPT 的插件创建方式选择 Tunnel，并指向这个 Tunnel ID。详情以
[OpenAI Secure MCP Tunnels](https://developers.openai.com/api/docs/guides/secure-mcp-tunnels) 为准。

`operator_web_tunnel_setup.py --profile <新的绝对目录> --tunnel-client <已校验的可执行文件>`
打开本机表单。可用 `--tunnel-id <已核实的连接编号>` 预填编号，格式错误在打开窗口前拒绝。
它只保存私有凭据文件与 `mcp-settings.json`，不联网、不创建账号资源、
不启动服务、不修改 Codex 配置，也不覆盖已有配置。表单可带入现有系统 HTTPS 代理，
仅用于这个客户端到 OpenAI 的连接；本地 MCP 和状态检查直连 loopback。

把生成的 `mcp-settings.json` 对象放入网页服务设置的 `mcp` 字段，并显式选择
`transport: mcp_v1`。第一次人工添加插件后，提交绑定：

```json
{
  "connection_id": "从本次 connection.json 读取",
  "tunnel_id": "从本次 connection.json 读取",
  "connector": {"id": "实际注册的精确插件 ID", "name": "实际插件名称"}
}
```

`connect` 要求当前服务实例、固定隧道身份和空闲状态一致，独占保存 `connector.json`。
之后显式启动同一个私有配置时加载准确绑定。旧 Quick Tunnel 插件不会被自动转换，
已有注册记录仍保留，不能把名称相似的条目当成同一个插件。

插件名称支持最多 64 个 ASCII 字母、数字、常用汉字或扩展 A 汉字，首字符之后也可用
空格和连字符。例如“Operator 固定连接”会原样保留；不做名称归一化或模糊匹配，仍须
核对实际注册的准确插件 ID。换行、零宽字符和其他不支持的字符在启动浏览器前拒绝。

## MCP 会话回收（2026-09-19）

端点保持 64 个会话、每会话 64 个请求身份和 900 秒期限。新初始化先清理已过期的空闲会话；仍满额时，只回收最久未使用且已经成功准备过 RPC 回复的空闲会话。初始化及通知本身不使新会话提前失效；HTTP handler 正在等待、或者准确的原生调用仍等待结果时，该会话保留，即便期限已过。

结束或取消后的 handler 在 finally 中解除占用；已结束的等待不再算忙碌。旧会话 ID 返回 404，未回收会话内相同请求编号仍拒绝；回收不复活旧 turn、已消费的读取键或调用。若所有 64 个名额都不能回收，仍明确拒绝新初始化，不能扩大内存上限或重发业务。

这依据 [MCP 2025-11-25 会话管理](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports#session-management) 的服务端终止规则，由本项目独立实现。服务诊断仅增加数量：池大小、忙碌、回收、过期；不暴露会话 ID、键、结果或私人 URL。配置、登录和固定连接无需重建。离线回归、保存服务的串行协议检查与原生 Desktop 执行分别记录，不能互相替代。

## 客户端与生命周期

- 审阅版本为官方 `tunnel-client` 0.0.12。二进制应按官方发布校验值验证后使用；
  本地配置固定二进制 SHA-256，文件变化拒绝启动，不自动下载或升级。
- Python 直接管理 `run --profile-file` 子进程；不安装上游 Codex 插件、后台任务或
  全局 profile。不启用其可选 Cloudflare、Harpoon 工具和自动打开网页功能。
- 配置只引用私有 key 文件；密钥不进入参数、网页子进程或状态。客户端环境使用
  明确允许项，阻止环境变量覆盖控制端地址、MCP 命令、日志和窗口设置。
- 本地 `/readyz` 本身不能证明控制端已接受连接。服务还读取官方成功轮询时间指标，
  只在本次进程有近期成功轮询时开放接纳。`check-connection` 对固定连接返回
  `transport_ready`，明确不代表 ChatGPT 插件授权或模型生成验收。
- 空闲连接故障暂停新请求，允许同一个客户端恢复控制端轮询，最多等待 60 秒。
  插件、端口、调用账本均保留；401/403、进程退出、观测异常和执行中断线终止服务。
  不重启子进程、不重新发模型请求、不重做 MCP 工具调用。
- 官方客户端自身会重试控制端轮询和符合其协议的同一结果投递。它们不能描述为
  “所有网络请求零重试”；Operator 的模型与工具不重放边界继续独立生效。
- 一个私有配置只允许一个所属实例。正常停止释放标记；崩溃残留标记阻止新实例，
  需先显式检查旧进程归属，不能凭旧状态文件自动接管或删除标记。
- 服务和隐藏浏览器默认均没有按时间自动退出的限制。单次请求超时、辅助窗口
  十分钟等待和每个服务实例 128 轮的防重放容量保留；空闲时间不会清空调用记录。
  达到容量后需要明确更换实例，不能丢弃记录后自动重做旧请求。

固定模式的本地 MCP 端点对准确的 OAuth 元数据发现 GET 返回 404，表示没有提供
OAuth 元数据；Host、Origin、工具路径、会话和本轮密钥检查仍有效。它不把本地
发现当成授权，也不会给 ChatGPT 插件或原生 Codex 增加执行权限。
