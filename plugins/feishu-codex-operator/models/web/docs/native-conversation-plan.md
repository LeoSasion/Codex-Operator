# 原生 Codex 对话改进计划

更新：2026-09-24。本页只保留当前计划；重复的逐轮验收已合并到[历史记录](native-web-history-20260924.md)。执行前读[当前项目记忆](native-web-experience.md)，原始通过、失败和未确认记录保留，不能据后续成功改判。

## 目标与参考

所有者要求原生 Codex 对话更流畅、少点击、少配置、少弹辅助窗口。Chat On Steroids 为首要研究参考；WebCodex、localmcp / MCPX、codex-chatgpt-web 冷置，仅有具体缺口才再查。不开发另一套工作界面、浏览器伴随扩展产品、Goal/Loop 或多智能体编排。重大内部改造先说明收益、迁移/恢复和验收范围。固定提交、采用机制和许可见[实现来源](web-background-sources.md)。

## 已落地的基础

| 能力 | 当前实现及证据 | 不包含的结论 |
| --- | --- | --- |
| 保存一次、准确复用 | `configure` 省略参数时只读校验已有设置；诊断区分访问、登记、程序与检查失败；实机重复复用未改保护文件或进程 | 不自动采用变更配置，不代表工具声明刷新已完成 |
| 隐藏页面准备 | 保存服务在接纳前准备一个空白临时聊天；消费时重新核验；准备过程零模型/MCP 请求 | 不宣称首字提速；底层 `serve` 不是所有入口自动预热 |

| 独立 provider 维护 | 只读识别 stale 代次；显式 `desktop-rebind` 保留准确 provider、原任务和配置原件 | 保存登记、新进程可见不等于运行中 Desktop 已采用 |

## 接下来仍需证明的体验

### 1. 准确连接的工具声明维护

比较完整语义声明，包括名称、描述、输入/输出 schema 和风险标记；不能直接照搬只比较部分字段的上游摘要。声明未变时零刷新；变化时只维护准确 app，在空闲实例操作一次并读回结果。未知结果保留，不能再次点击或自动重试。

验收：隔离测试覆盖字段变化及未变复用，再检查当前页面真实刷新次数和结果。已有连接、授权和登录继续使用。此项仍待实现与验证，不因保存入口已复用而算完成。

### 2. 页面准备后的连续任务与停止体验

隐藏准备已实现，后续重点是当前版本下的真实连续对话、停止后新输入、失联与重新打开。保留已完成页的只读 `inspect`；`assist` 是空白聊天恢复，不用于保存现场。历史 CLI 曾通过两轮上下文和取消复用，这不能替代当前主窗口的停止按钮与三轮任务验收。

验收：同一准确原生任务三轮新输入，逐轮核对当前需求、完整历史、工具与结果身份；正常路径无抢焦点/辅助弹窗。取消请求保持终态，不重放，只有经准确空闲核验后才接纳不同新输入。测量本地准备时间与上游生成时间分别报告。持续验证提示须实际观察后才请求用户操作；页面看不到就记录未确认。

### 3. 原生任务入口与模型选择

当前基线是官方直连加独立 Web provider，专用 Web 任务由助手配置。CLI 0.155.0-alpha.16.3 的合成检查证明：新任务可绑定未列于主 `model/list` 的准确 Web provider；首轮落盘后新进程可恢复该绑定。新进程也能显式切换提供方；同进程已加载任务的恢复/设置更新探测仍把请求送到原提供方。因此菜单出现、配置返回成功和实际去向必须分别核对。

已有专用任务在助手任务工具转交下完成过文本接续；该转交不是手动输入框。下一步验证当前 Web-only 搜索路径下的主窗口新任务可见性、打开、输入与继续，再评估受支持的模型选择入口。不能为了跨 provider 切换自动重启 Desktop、改既有任务历史或恢复全局路由。

验收：新任务接入、同任务选择、实际请求去向、历史接续、读改测和原生审批各有准确证据。若原生接口仍不支持切换，如实保留缺口；提出替代架构时先给出官方直连影响、容量/辅助请求验证和恢复方案。历史隔离统一路由的成功不代替当前直接 provider 的验收。

### 4. 搜索来源与当前任务正确性

保留正常搜索配置。Web 的 `web_page_auto_v1` 只证明适配路径；实际搜索、引用有效性、来源是否支持结论分别验收。GLM-5.3 官方 hosted 搜索、GLM-5.3 Flash 的 Codex 搜索和 DeepSeek 的端点能力分开，依据[在线模型证据](../../api/docs/official-online-models.md)。

验收：新问题指定明确目标来源，检查实际回答和来源内容；同时确认无额外 Codex 搜索执行。必须读完完整索引上下文，实际工具处理当前请求。只返回链接、读取所有页面或 HTTP 200 都不能代替这些检查。旧 citation/context 失败不重试。

## 变更与交付顺序

1. 用当前源码、保存登记、准确进程及既有证据确定缺口，避免重新实现已完成能力。
2. 完成一个明确行为修改后运行相关边界检查；部署前按范围做跨层回归与发布审计。
3. 部署核对空闲状态、源代码代次、保存原件及恢复路径；不知道是否执行过的操作不重复。
4. 用已授权的新测试验证实际行为，分别记录源码、隔离、本机部署与主窗口证据。
5. 将稳定经验写入当前指南，日期、失败与一次性 workaround 归入历史。最终按用户实际少做的步骤报告，不用测试数量代表全部产品完成。
