更新：2026-10-02。仅适用于本机已观察的 `huihui-qwen3.8-27b-abliterated`，对应
`Huihui-Qwen3.8-27B-abliterated-UD-DW-Q4_K_S.gguf`。型号名称本身不授权模板替换。

早期真实 Desktop 新输入保留为失败。LM Studio 日志记录 Jinja 的
`System message must be at the beginning.`；当前模板接受开头的连续 system/developer，
但拒绝 user 后的已有系统消息。Desktop 的 Default Mode 开发者消息属于这类顺序。
这个原因已由无推理渲染验证，不推广为所有 HTTP 500 的解释。

`operator_core/lmstudio_template.py` 只准备准确 SHA-256 绑定的候选，不写配置、不加载
模型、不推理。预测模板原摘要为 `d6faec65555d20276f5bb0bed387e7776b484768ff280c18d69161abc4dfb769`；
已观察的加载表示原摘要为 `12827f24b742ea4e80cdc12dbcf9622227056b9f797252a3149263d4f9aaadce`。
后者保留引擎原有的 JSON safe filter，两种表示分别绑定，未知变化直接拒绝。

候选只将原拒绝语句替换为同位置的 system 消息块，使用原系统内容渲染器并保留边缘空白。
开头的原合并行为、用户、助手、推理和工具分支保持原字节。不解析普通文本为指令、不
修改 Responses 的源角色或存储历史，也不删除权限说明。系统图片、视频和未知形状仍拒绝。
30 项离线渲染检查通过；实际 LM Studio SDK 的四项只读渲染检查核对旧用例字节不变和
新增块的准确顺序。渲染通过不等于模型理解或工具执行通过。

文件测试。另一个新文件案例完成手动原生压缩；替换历史保留原数字和标记，压缩后只读
新增文件即给出正确接续答案。原生校验曾拒绝模型多给的参数，随后新调用才真实执行；
拒绝记录完整保留，不能算作工具成功或审批授权。期间另一个独立案例的 HTTP 500
仍失败，未取得可归因证据。这些实机结果使用 26.928.3736.0 / CLI 0.159.2，不自动
继承为所有模型、全容量压缩、自由格式 patch、审批或更新后 Desktop 的通过结果。
