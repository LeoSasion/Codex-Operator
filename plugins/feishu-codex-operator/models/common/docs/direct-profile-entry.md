## 入口与会话

原生入口选择官方默认提供方。拓展入口选择一个已核验的自定义提供方；API 和 Local 的 Responses 请求直达已声明端点。切换提供方需要正常关闭 Desktop，由官方应用自己在下一次启动时恢复原会话。菜单在该提供方范围内列出模型；不同端点的模型不能仅靠追加名称实现逐回合切换。

Web 仍使用自己的独立受管服务和原生工具桥；它的原生入口接入另行绑定、验证，不经这一 API/Local 原型推定已经完成。官方原生请求不应为了 Web 接入而经过该桥。

当前 CLI 0.159.2 的标准和实验 schema 中，`model/list` 的模型项、`turn/start` 和 `thread/settings/update` 仍无提供方选择字段，开始、恢复及分叉会话才有 `modelProvider`。项目配置不能代替主窗口的提供方选择。新增隔离检查在同一个 UUID 中完成三次官方客户端启动、恢复及新输入，实际目标依次为原生、自定义、原生的三个直接请求，公开文字历史完整保留；没有使用 Operator 路由器或真实账号。它证明客户端恢复机制，**不证明真实 Desktop、模型能力或所有历史通过**。

另一独立合成检查保留外部 `reasoning_text` 后，第三轮被模拟原生端点以非空 `reasoning.content` 拒绝。它是通过的拒绝边界检查，原生返回这一轮仍为失败。此前真实旧 Local 聊天切回原生的 `array_above_max_length` 也仍为失败；不删除历史、不将外部推理变成答案、不自动重试。

## 配置投影与持久入口候选

[`operator_direct_profile.py`](../../../scripts/operator_direct_profile.py) 提供纯配置投影及恢复函数，并预览一个已经完整安装、源内容一致的原生 profile。它复用 [`operator_native_models.py`](../../../scripts/operator_native_models.py) 的显式端点合同，不增加网络代理、工具执行或模型请求。

投影仅选择模型、提供方、目录、推理档位及该模式的搜索配置。原生选择字段保留为精确的注释行，其余字节不变；恢复可以保留后来在受管区外更改的 CUA pipe 和其他用户设置。准确、完整、全注释的旧 loopback 块保留在文件首部。未知、重复、活动或不完整标记、已改受管内容、源文件变化及不支持的 TOML 形状均拒绝；不会规范化或覆盖它们。

这份内存恢复说明只描述投影，**不提供安装归属、认证、持久事务或激活权限**。工具没有 `apply`、启动、停止服务或重放命令。现有统一路由必须先经过独立原生恢复，不能由本模块静默迁移。预览可以读取私有的拟恢复原生快照，但会明确 `baseline_is_live_config=false`；不能把这种预览当作已恢复的当前配置。

17 项新增检查覆盖直接端点、原权限、逐字恢复、CRLF/BOM/Unicode、旧注释块、后续设置、冲突和变更内容、伪造投影说明及只读预览。另有现有原生 profile 与恢复回归通过。当前实际保存的 2 项 API、5 项 Local 安装均完成只读投影预览；没有向它们发送新请求，也不建立它们在当前 CLI 或 Desktop 的能力验收。

后续实机恢复：所有者报告原生重开后，首次观察的磁盘仍选择旧统一提供方。现有独立恢复工具随后实际完成受管路由移除、旧入口停用及原生保护恢复，保留全部原件。新只读 App Server 的 `config/read` 加载官方默认提供方，单次有界 `model/list` 返回八个原生型号；配置和缓存均未被该检查改动。七个 profile 又完成了绑定当前真实原生配置的预览。所有者再次正常重开后，准确官方包的全部进程都生于这次实际恢复之后，当前配置仍为官方默认提供方，仅工具连接的 CUA pipe 字段变化。这通过了配置与启动顺序核对，不代表已读取任一旧任务的当前上游包或完成语音验收。没有发送诊断模型请求。拓展入口仍未部署。

[`operator_direct_entry.py`](../../../scripts/operator_direct_entry.py) 现提供源内容绑定的 `prepare`、`preview`、`activate` 及只读 `maintenance-status`。每项显式 API/Local profile 的私有计划绑定解释器、源码、独立恢复工具及完整安装文件；当前原生配置在预览时重新读取，不因后来的 CUA 管道变化永久失效。API 仅检查已保存 Windows 用户或机器环境中的密钥是否存在，用户值优先；不复制、设置或输出凭据，也不把测试进程独有环境当作官方包可继承的环境。

激活需要新的配置摘要及计划摘要。它要求正常关闭 Desktop、准确旧后台进程缺席、路由端口可独占及待处理消息/回调为空；独立 Web 服务只可处于已核对的空闲状态。旧统一激活目录必须经独立审查保留后退役、归档。每次写入前先保留完整原件、候选、投影、profile、计划及不可重放的意图，再使用既有 Windows 文件身份见证事务替换配置。未完成、失败、孤立或不确定的周期不得重新消费；新的周期须先有可核验的独立原生恢复回执。控制器从不启动应用、服务或执行模型请求。

拓展启动脚本增加独立 `direct_profile` 选择窗口，原生保护标记始终保留。选择仅作用于下一次启动，不改运行中窗口的模型。冷启动重新核对官方包身份；自定义配置成功后，在请求 Shell 启动前保留独立启动意图和固定结果，不能把 Shell 已请求当作主窗口验收。取消、失败和不确定结果不自动重试。配对构建绑定准确选择索引、解释器、源码、profile 计划及保留的旧入口链；旧安装的运行时归属仍保持未解决，不能制造首次安装权限。

独立 PowerShell 恢复验证持久周期、原件、候选和固定生成语法，逐字恢复已记录的原生选择，并保留受管区外的后续设置；不依赖 Python、模型服务或可移除 runtime。严格 v1 投影不变，新的显式 v2 仅允许相同模型在 manifest 已列出的推理档位间选择。改变端点、目录、模型身份、其他选择或原件均停止。新的直连恢复另保留原生完成快照及时间：只有其完整、源内容绑定的回执可用于运行窗口检查，单一后来 CUA pipe 写入不再误判为旧窗口。旧恢复文件和目录时间不会自动获得这种权限。

## 研究来源

首要参考仍为 [Chat On Steroids](https://github.com/totec448-spec/chat-on-steroids/tree/2524773c8b4389c27f6c420c6a27f5a14bacbe4d)。当前固定提交的 [Desktop bridge 草案](https://github.com/totec448-spec/chat-on-steroids/blob/2524773c8b4389c27f6c420c6a27f5a14bacbe4d/docs/codex-desktop-bridge.md) 仍没有生产入口；它的准确任务身份与 Desktop 所有权边界保留，不引入单独工作界面、伴随扩展、Loop 或多智能体编排。

为入口隔离这个具体缺口，额外核对 [Codex Desktop Custom Models 的固定架构](https://github.com/ademisler/codex-desktop-custom-models/blob/10a8954ea2d8fd57d6b8943dc3c035df2e18e1ab/docs/architecture.md)（MIT）。它的 macOS/Linux app clone、独立 home 与 Chat Completions 代理不能满足本项目保留同一官方应用、同一会话及直连的目标，因此仅借鉴提供方隔离的研究方向，未复制代码、安装产品或移植其状态和自动化。各项许可、历史参考及实际采用仍见[来源登记](../../web/docs/web-background-sources.md)。
